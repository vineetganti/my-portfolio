## What are the basic components of a neural network?

### What is a layer? What is a parameter?

**What are the components of a neural network model?**
- A highly flexible function approximator composed of several interconnected computational elements.
- The core structure typically consists of Neurons (Nodes) which are the fundamental processing units. Each neuron receives one or more inputs and performs a weighted sum and applies an activation function to the result.
- Neurons are organized into layers
    - Input layer receives raw data. No computation other than passing input features through.
    - Hidden layers perform complex feature extraction and transformation through successive applications of weighted sums and activation functions.
    - Output layer produces the final predictions or classifications.
- Weights represent the strength of connection between neurons in different layers. Determine influence of an input on the output of a neuron. Adjusted during training to minimize prediction error.
- Biases allow activation function to be shifted, effectively enabling the neuron to activate even if all inputs are zero.
- Activation functions are non-linear functions applied to the output of each neuron's weighted sum. Critical for enabling the network to learn non-linear relationships.
    - Without non-linearity, a deep neural network would simply be equivalent to a single-layer perceptron, severely limiting its expressive power.
- Loss funnction or cost function quantifies discrepancy between network's predictions and actual target values. A numerical measure of how wrong the model's predictions are.
    - The objective of training is to minimize this loss function over the training data, guiding the parameter updates.
- Optimizer is an algorithm used to adjust the network's weights and biases during training by minimizing the loss function.
    - Optimizers typically employ gradient-based methods, such as Stochastic Gradient Descent (SGD) and its variants (Adam, RMSprop), to iteratively update parameters in the direction that reduces the loss.

**Which ones are trainable parameters, and which are constants?**
- Trainable parameters are the numerical values within the neural network that are adjusted by the optimization algorithm during the training process. Examples are weights, biases and convolutional kernels.
    - Their primary role is to learn the underlying patterns and relationships in the data, enabling the network to map inputs to desired outputs. They are the components that hold the 'learned knowledge' of the network.
- Constants establish the framework and operational rules within which the trainable parameters are learned.
    - These are elements of the neural network that are fixed prior to or during training and are not adjusted by the optimization algorithm based on gradients from the loss function.
    - Constants typically define the network's architecture, operational logic, or control the training process itself. They are either structural elements or hyperparameters set by the model designer and remain static or are manually adjusted.
- In essence, trainable parameters are the adaptive elements that encode the network's learned representations, modified through data exposure and gradient-based optimization. Constants (or hyperparameters) establish the framework and operational rules within which these parameters are learned, determined by design choices rather than direct data-driven updates during training.

**Which are used during forward pass, and what extra is used during training?**
- The initial data vector (where n is the number of features) that serves as the network's starting point.
- Learnable parameters comprising weights and biases for each layer and activation functions to bring in non-linerarity.
    - They scale and shift the input signals, forming the core of the linear transformation within each neuron.
- Activation functions: Transform the summed weighted inputs into an output that is passed to the next layer. Without them, a neural network, no matter how deep, would only be able to learn linear transformations.
- The final result generated by the network after the input has traversed all layers.
- The training phase is useful, extending the forward pass by incorporating mechanisms to learn from errors and iteratively adjust the learnable parameters.
    - Target labels (Ground Truth): Benchmark against network predictions for supervised learning.
    - Loss Function (Cost Function): A scalar-valued function that quantifies the discrepancy between the network's prediction and the true label. Its primary purpose is to provide a measurable objective for optimization.
        - The objective function that the training process aims to minimize. A lower loss indicates a better-performing model.
            - Examples include Mean Squared Error (MSE) for regression, and Cross-Entropy loss for classification. 
    - Gradients: Vectors of partial derivatives of loss function wrt each learnable parameter.
        - Used by the optimizer to determine how to adjust parameters to decrease the loss. They are computed efficiently via the backpropagation algorithm, which uses the chain rule of calculus.
            - The core idea of backpropagation is to propagate the error backwards through the network, layer by layer, calculating the gradient for each parameter.
    - Optimizer: Utilize computed gradients to iteratively update the network's learnable parameters, minimizing loss function.
    - Learning rate: Crucial hyperparameter that controls step size taken by the optimizer when adjusting parameters. Dictates how aggressively the model learns.
        - A high learning rate can lead to instability and divergence, while a low learning rate can result in slow convergence or getting stuck in local minima.

### How are parameters stored? How does PyTorch manage them?

**How are parameter tensors allocated in memory?**
- Allocated as n-dimensional arrays, managed by underlying deep learning framework's runtime and hardware interfaces.
- Encapsulate numerical data and are associated with a specific device and data type. torch.sensor is the fundamental data structure representing a multi-dimensional matrix. It acts as a handle to a block of memory, which can reside on either the CPU (host memory) or a GPU (device memory).
- Memory Allocation by Device:
    - CPU Memory (Host): When a tensor is created on the CPU, PyTorch's C++ backend (powered by the ATen library) uses standard system memory allocation routines (e.g., malloc or equivalent) to reserve a contiguous block of RAM. This is typically the default device.
    - GPU Memory (Device): For GPU allocation, PyTorch interfaces with the GPU's programming model, primarily CUDA for NVIDIA GPUs or ROCm for AMD GPUs. It calls low-level runtime APIs (e.g., cudaMalloc in CUDA) to request dedicated video RAM (VRAM) from the GPU's memory controller. The tensor then stores a pointer to this GPU memory block.
    - Device Transfer: Moving a tensor from CPU to GPU (e.g., tensor.to('cuda') or model.cuda()) involves copying the tensor's data from host RAM to device VRAM. This is a crucial step for leveraging parallel computation, and the data transfer bandwidth can be a significant bottleneck.
- Memory Layout and Contiguity: Tensors are often stored in a contiguous block of memory to optimize access patterns and computational efficiency. PyTorch internally manages strides to handle non-contiguous views without copying data, but explicit .contiguous() calls can enforce contiguity when necessary, potentially incurring a copy operation.
- Data Types and Precision: The amount of memory allocated is directly proportional to the number of elements and the data type (e.g., torch.float32, torch.float16, torch.bfloat16, torch.int8). Lower precision types (float16, bfloat16) reduce memory footprint and can accelerate computations on compatible hardware.
- Parameter Management in nn.Module: When you define a neural network using torch.nn.Module, parameters are registered using self.register_parameter() (or implicitly via nn.Parameter). This allows the module to track them, move them between devices, and include them in the optimizer's parameter list for gradient updates.

**Do all parameters have to be moved to GPU? When does this happen?**
- PyTorch operations are device-agnostic in their definition, meaning the same operation can run on CPU or GPU. However, they strictly require all participating tensors to be on the same computational device (either CPU or a specific GPU) to execute successfully. You cannot perform an operation between a tensor on CPU and a tensor on GPU directly.
- Not all parameters must be moved to the GPU, but for any computation to leverage GPU acceleration, the relevant parameters and input data must reside on the same GPU device as the operation itself.
    - Parameters are moved to the GPU when a user explicitly requests it or when an underlying framework (e.g., for distributed training) orchestrates this placement. This typically occurs just before or at the point of computation, enabling the GPU to perform matrix multiplications and other operations efficiently.
        - Explicit User Control in PyTorch: The most common scenario for moving parameters to the GPU involves explicit placement using PyTorch's API.
            - Moving Individual Tensors: Individual tensors can be moved using the .to(device) method or its convenience alias .cuda().
            - Moving Entire Modules: For instances of torch.nn.Module (which represent neural network layers or full models), calling module.to(device) conveniently moves all internal parameters (e.g., weights and biases) and buffers (e.g., batch normalization running statistics) of that module to the specified device.
        - Implicit and Orchestrated Placement for Advanced Setups: In more sophisticated or large-scale training scenarios, parameters might be moved dynamically, partially, or managed by distributed frameworks.
            - Data Parallelism: Frameworks like torch.nn.DataParallel or torch.distributed.DistributedDataParallel typically replicate the model on multiple GPUs. Each replica will have its parameters on its respective GPU, allowing each GPU to process a batch of data in parallel.
            - Model Parallelism and CPU Offloading: For extremely large models that exceed the memory capacity of a single GPU, techniques like model parallelism (sharding model layers across multiple GPUs) or CPU offloading (moving less frequently used layers or parameters to CPU memory) are employed. In these cases, parameters are only loaded onto the active GPU as needed for computation, dynamically moving them back and forth.
            - ZeRO (Zero Redundancy Optimizer): Advanced optimizers like ZeRO (part of DeepSpeed) further optimize memory by partitioning model states (optimizer states, gradients, and parameters) across devices, meaning not all parameters reside fully on any single GPU at all times, reducing memory footprint.

**Can multiple models share parameters?**
- Yes, parameter sharing enables efficiency, regularization and exploitation of shared representations across different parts of a network or distinct models.
- Parameter sharing, often referred to as weight sharing, is an architectural pattern where a single set of trainable parameters (weights and biases) is used by multiple computational units or layers within a neural network, or even across separate model instances.
- The core principle behind parameter sharing is the enforcement of an inductive bias. If certain transformations or feature extractions are expected to be universally useful or perform similar operations across different contexts (e.g., different input locations in an image, or different but related tasks), then sharing parameters allows these components to learn a unified, robust representation.
- In PyTorch, parameter sharing is elegantly managed by Python's object referencing and PyTorch's module system. It's achieved by having multiple nn.Module instances or sub-modules reference the same underlying torch.nn.Parameter objects.
    - When an nn.Module is initialized, its parameters are typically registered as attributes. If multiple modules or layers are assigned the same nn.Parameter instance, or if a sub-module is passed by reference to multiple parent modules, they will all operate on the exact same underlying tensors. During backpropagation, gradients for these shared parameters will accumulate correctly.
- Common Application Patterns:
    - Siamese Networks: Consist of two or more identical subnetworks (sharing all parameters) that process distinct inputs to learn a similarity metric or embed inputs into a common space for comparison (e.g., face recognition, signature verification).
    - Multi-Task Learning (MTL): A single model is trained to perform multiple related tasks simultaneously. A common 'backbone' network shares parameters to learn general features, while task-specific 'heads' branch off from these shared layers, each with their own unique parameters.
        - This setup encourages the shared layers to learn features that are useful across all tasks, often leading to better generalization and data efficiency compared to training separate models.
    - Encoder-Decoder Architectures: In certain sequence-to-sequence models or autoencoders, the embedding layer or parts of the encoder and decoder might share weights. This is particularly effective when the input and output vocabularies are identical, enforcing a consistent semantic space.
        - Example: Sharing the input and output embedding matrices in a Neural Machine Translation (NMT) model, where the source and target languages use the same vocabulary, can lead to improved performance and reduced parameters.
    - Generative Adversarial Networks (GANs): While typically Generator and Discriminator are separate, some advanced GAN architectures or component sharing (e.g., partial weight sharing in spectral normalization layers or shared feature extractors in conditional GANs) might implicitly or explicitly leverage parameter sharing principles.
